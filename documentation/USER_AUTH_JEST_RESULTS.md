## Commands

```sh
# All focused user/auth unit and HTTP tests; requires explicit PostgreSQL test URLs.
npm run test:user-api

# Same scope, with enforced coverage thresholds and reports.
npm run test:user-api:cov

# Focused unit/runner tests, without a running database.
npm run test:user-api:unit

# Interactive watch for the scoped unit tests.
npm run test:user-api:watch
```

The aggregate runner loads `.env`, validates both test URLs before connecting, checks connectivity and starts only the focused Jest configuration. It fails rather than silently accepting skipped database tests. Existing `test:auth` and `test:users` remain available for their original suites.

Commands executed during verification: the starting scoped baseline, focused coverage runs, `test:user-api:unit`, `npm run build`, `tsc --noEmit --incremental false`, scoped `oxlint`, and `git diff --check`. Watch mode was not started because it is interactive.

## Isolation and failure testing

- Each HTTP suite creates its own random, guarded `user_api_test_*` schema and applies committed migrations there.
- Each case creates independent user data; shared configuration is restored, and administrative pagination tests no longer depend on a previous case's records.
- The fixture owns one explicit loopback HTTP listener so concurrent requests cannot auto-close one another's server.
- Per-user credential races use promise barriers, not arbitrary sleeps.
- PostgreSQL triggers inject revocation failures, proving user/version/session changes roll back together. Failure injections are removed in `finally` blocks.
- Outage tests use an unreachable runtime database connection while leaving the real PostgreSQL instance running; they assert redacted failures and no writes.
- Nest, Prisma and pg resources are closed, and only the exact generated schema can be dropped. The separate test database is retained for future test runs. Final verification found zero generated test schemas and zero public tables in that test database. The one schema left by the interrupted run was explicitly removed after the completed runs; application tables were not used or changed.

One new outage fixture initially constructed several requests before awaiting them; this was corrected to construct requests sequentially. A later coverage retry was interrupted after slow teardown; the fixture was hardened with an explicitly owned listener, and completed coverage runs passed. No API behavior defect was found by this test expansion. Production code changes are limited to extracting the existing CORS settings into a shared helper so the tests exercise the same configuration as bootstrap.
